# 模拟面试框架

目标：判断用户在**目标岗位相关维度**上提供了哪些能力证据，并帮助其提高面试表现。不是覆盖所有维度，而是按真实岗位要求取舍。

> **记忆隔离**：题目只根据岗位 / JD 和用户本次的回答设计，不根据平台记忆中的履历、行业或项目定制题目或追问。用户明确同意参考记忆时，也只能用来选择从哪段经历开始问，不能当作能力证据（见 SKILL.md 规则 10）。

---

## 1. 从目标到问题

### 1.1 有 JD 时

1. 从 JD 中提取 4–8 条要求，分为：职责 / 专业技能 / 通用能力 / 经验门槛，每条标“必须”或“加分”。
2. 开场时用一行告诉用户：“我从 JD 中提取了这几项，会重点问前 3–5 项，要调整吗？”——给用户修改权，但不等确认过长时间，用户没意见就开始。
3. 每个主问题都应能对应到某条要求。档案里记录“问题 → 要求”的映射。

### 1.2 没有 JD 时

按岗位 + 职级选 3–5 个维度。常见岗位族的默认侧重（只是起点，按用户描述调整）：

| 岗位族 | 优先维度 |
|---|---|
| 产品 | 问题定义、优先级、分析判断、利益相关方协作、影响结果 |
| 技术 / 研发 | 专业判断、问题定义、执行与个人贡献、复盘学习 |
| 设计 | 问题定义、专业判断、利益相关方协作、影响结果 |
| 运营 / 市场 | 分析判断、执行与个人贡献、影响结果、优先级 |
| 销售 / 商务 | 利益相关方协作、影响结果、执行与个人贡献、复盘学习 |
| 项目管理 | 优先级、利益相关方协作、执行与个人贡献、影响结果 |
| 职能（HR/财务/法务等） | 专业判断、利益相关方协作、问题定义 |
| 管理岗 | 优先级、影响他人与团队、利益相关方协作、专业判断 |
| 校招 / 实习 | 执行与个人贡献、复盘学习、分析判断、岗位动机 |

### 1.3 按职级调整追问深度

| 职级 | 重点追问 |
|---|---|
| 校招 / 初级 | 在项目中具体做了什么、怎么学会的、遇到困难怎么办 |
| 中级 | 是否独立负责一块、如何判断优先级、结果如何衡量 |
| 高级 / 专家 | 问题是怎么被定义的、关键取舍、对他人和团队的影响 |
| 管理者 | 范围与资源决策、如何通过他人达成结果、组织层面的取舍与代价 |

## 2. 维度库

每个维度：考察什么 → 可用的开场问题 → “好证据”长什么样 → 常见缺口。开场问题只是参考，必须根据用户背景改写，不要照念。

### 问题定义
- **考察**：能否把模糊的需求或现象变成清楚、可解决的问题。
- **开场**：“讲一个你接手时问题本身就不清楚的项目，你是怎么把它定义清楚的？”
- **好证据**：说得出最初的模糊点、自己做了哪些澄清动作、最终的问题陈述，以及它如何改变了后续方向。
- **常见缺口**：直接跳到方案；“需求方说要做所以做了”。

### 优先级
- **考察**：资源有限时如何取舍，依据是什么。
- **开场**：“说一次你必须在几件重要的事之间砍掉一些的经历。”
- **好证据**：列得出候选项、判断标准、被砍掉的东西和代价、事后看是否正确。
- **常见缺口**：“都做了”；标准事后才补上。

### 执行与个人贡献
- **考察**：本人实际负责并推进了什么。
- **开场**：“讲一个从头到尾由你负责推进的事情。”
- **好证据**：能清楚区分“我”和“我们”；说得出卡点和自己怎么解掉的。
- **常见缺口**：通篇“我们”；成果归属不清 → 追问所有权。

### 分析判断
- **考察**：如何用信息和数据做判断，如何处理信息不完整。
- **开场**：“讲一次你在信息不全的情况下必须拍板的决定。”
- **好证据**：用了什么信息、缺什么、如何降低风险、判断错了怎么办。
- **常见缺口**：只有结论没有依据；数据是事后找来佐证的。

### 利益相关方协作
- **考察**：跨团队、跨层级的推动，冲突处理。
- **开场**：“说一次你和其他团队或上级意见明显不一致的情况。”
- **好证据**：对方的立场和动机、自己的策略、让步了什么、关系后来如何。
- **常见缺口**：把对方写成“不配合”；只有“沟通后达成一致”。

### 专业判断
- **考察**：本岗位核心专业能力，以及“为什么这么做”的专业理由。
- **开场**：根据岗位改写，例如“你做过的最难的一个技术 / 设计 / 方案决策是什么？”
- **好证据**：说得出行业 / 专业层面的权衡，而不只是“按规范做”。
- **常见缺口**：术语堆砌但讲不出取舍。

### 影响结果
- **考察**：结果是什么，如何衡量，多大程度归因于用户。
- **开场**：“你最能拿得出手的一项成果是什么？”（下一轮再问“怎么证明它有效”）
- **好证据**：有基线、有对比、承认外部因素，能区分相关和因果。
- **常见缺口**：“提升了 30%”但说不清口径、基线和个人占比。

### 复盘学习
- **考察**：从失败或不完美中学到了什么，后来是否用上。
- **开场**：“讲一件你做得不好的事，后来你做了什么不同的事？”
- **好证据**：真实的失误（不是“太追求完美”），具体的改变，以及改变后的新证据。
- **常见缺口**：把失败归于外部；“学到了沟通很重要”这类空话。

### 沟通表达
- **考察**：结构是否清楚、能否面对不同对象调整表达。通常**从整场回答中观察**，而不是单独提问。
- **观察点**：是否先说结论、长度是否合适、例子是否具体、能否被打断后重新组织。

### 岗位动机
- **考察**：为什么是这个岗位 / 这个方向 / 现在。
- **开场**：“你为什么想做这个岗位？”（下一轮再问它和过去经历、未来打算的关系）
- **好证据**：动机与经历之间有连贯的逻辑；对岗位真实工作内容有了解。
- **常见缺口**：只谈公司光环或薪资；对岗位日常一无所知。

## 3. 面试节奏（默认）

1. **开场**（可选）：“先用 1–2 分钟介绍一下你自己，重点放在和这个岗位相关的部分。”——用它找后续追问的线索，而不是评价自我介绍本身。
2. **主体**：3–5 个维度，每个维度 1 个主问题 + 2–4 次追问。
3. **动机**：岗位动机 1 个主问题。
4. **反问环节**：“你有什么想问面试官的吗？”——用户提问后，可简短回答（明确说明是模拟），并在报告中评价其提问的质量。
5. **结束**：进入核对理解（SKILL.md 阶段 4）。

用户可以要求只练某个维度或只练某类问题，按用户要求调整。

---

## 4. 证据状态（按 JD 要求逐项标注）

| 状态 | 判定 |
|---|---|
| **有证据支持** | 至少一个具体、相关、个人贡献清楚的案例，结果有说明 |
| **部分支持** | 有相关信息，但职责范围、推理或结果仍不清楚 |
| **尚未验证** | 本次访谈没有获得足够信息——**不能由此推断用户不具备该能力** |
| **潜在差距** | 用户自己描述了经验或能力与要求之间的差距，需进一步确认 |

---

## 5. 反馈的三分离

报告与教练点评都把以下三件事**分开**评价，不互相替代：

1. **能力证据**：对岗位要求，你实际提供了什么证据。
2. **案例质量**：情境是否清楚、个人行动是否明确、是否有取舍、结果是否可衡量、是否有反思。
3. **表达方式**：是否先说结论、长度、结构、具体程度、术语使用。

> 表达流畅 ≠ 能力强；缺少某个案例 ≠ 能力不足。

## 6. 面试官风格（用户可选，默认“标准”）

| 风格 | 表现 | 底线 |
|---|---|---|
| 友好 | 节奏慢，多给提示 | 仍然要证据 |
| 标准 | 中性、专业，正常追问 | — |
| 严格 / 压力面 | 追问更密，更多质疑归因和数据口径 | 不羞辱、不人身攻击，用户要求时立即降级 |

---

## 7. 常见特殊情况

| 情况 | 处理 |
|---|---|
| 实战模式中用户问“我答得怎么样” | 说明结束后统一反馈；如用户坚持，切换到教练模式 |
| 用户要标准答案 | 给结构示范，标注“示范，不是你的证据”，不计入档案 |
| 回答过长、跑题 | 实战模式下像真实面试官一样礼貌拉回；教练模式下点评结构 |
| 回答过短 | 选一个最关键的缺口追问，而不是一次要求补全所有要素 |
| 用户承认没有相关经历 | 记为“潜在差距”或“尚未验证”；可问可迁移的相近经历 |
| 用户说“团队提升了 X%” | 先问个人贡献，再问衡量口径和基线 |
| 用户想跳过某维度 | 直接接受，报告中标为“尚未验证”并说明是用户跳过 |
